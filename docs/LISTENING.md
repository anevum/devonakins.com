# Listening / In the Zone — staged integration

Status: SOURCE IMPLEMENTATION / REVIEW ONLY. Nothing here authorizes public Spotify data sharing, release, or production deployment.

## Purpose

The site-wide **In the Zone** ticker is a chosen convention: Spotify playback suggests Devon is in his coding zone. This is **not** a claim that an editor, terminal, or GitHub is actively recording work. The dedicated `/listening/` route is an accessible, private-by-default view of the same presence projection.

The existing V2 portrait, GPT snapshot, portfolio wordmarks, theme controls, navigation, routes and Cloudflare Worker architecture are preserved. No new third-party JavaScript, analytics or dependency has been introduced. No audio is auto-played or streamed.

## Current implementation

- Shared shell: `v2/index.html`, `public/v2/listening.css`, `src/terminal.ts`
- Canonical deep link: `/listening/` generated by `scripts/pages.mjs`, `src/content.mjs` and `src/immersive-routes.mjs`.
- Same-origin read-only JSON endpoint: `GET /api/listening/now`; `HEAD` responds with headers and no body. Unsupported methods return 405. The response is marked `private, no-store` and is not CDN-cacheable.
- Worker `src/worker.mjs` uses `src/spotify-presence.mjs`, which is included by `scripts/build-worker.mjs` in the packaged Cloudflare Worker.
- One browser poller refreshes every 90 seconds while the document is visible. Spotify polling itself is capped to one request per Worker isolate per 60 seconds when public sharing is on. Spotify 429 responses now trigger an in-isolate cooldown honoring Retry-After (bounded to 1–15 minutes), but this is NOT a cross-isolate quota guarantee. Production requires traffic/load validation or a shared coordinator before a public rollout.

### Local-only owner authorization (implemented, not yet performed)

The Spotify app must be registered in the [Spotify Developer Dashboard](https://developer.spotify.com/dashboard) and the owner must consent on a computer where Node.js 22 is available. Register the callback `http://127.0.0.1:8787/callback` (an exact loopback IP is permitted; `localhost` is not). In Spotify Development Mode, the app owner needs Spotify Premium.

Run this from the website repository on the **owner's local computer**, not on a public server:

```sh
node scripts/spotify-connect.mjs --client-id YOUR_SPOTIFY_CLIENT_ID
```

The command prints a Spotify authorization URL for the owner to open on that same computer; the temporary HTTP server binds only to `127.0.0.1`, validates a high-entropy OAuth state, exchanges the code using PKCE, and requests only `user-read-currently-playing`. There is no public callback, deployed admin login, or third-party auth proxy.

On success the utility creates mode-0600 `.local/spotify-refresh-token` and `.local/spotify-connection.json` (in an ignored directory). The latter contains only non-secret metadata, including authorization date and a six-month reauthorization date. No token values appear in its console output. Keep the token out of chat, tickets, screenshots, Git, and public URLs. To reauthorize after six months, use the same command with `--replace`; this overwrites the **local** files only.

No credentials are installed into Cloudflare automatically. If owner approval and a separate security/release review are satisfied, store `SPOTIFY_CLIENT_ID` in the Worker environment and `SPOTIFY_REFRESH_TOKEN` as a private Worker secret. A **PKCE** refresh uses `client_id` and does not require `SPOTIFY_CLIENT_SECRET`. The latter is supported only for credentials originally issued through the confidential authorization-code flow. Keep `SPOTIFY_PUBLIC_NOW_PLAYING` disabled throughout authorization and integration checks.

Spotify refresh tokens now expire six calendar months from owner authorization, regardless of how often an access token is refreshed. Reauthorization does not automatically rotate the secret deployed to the Worker; that is a separate owner-controlled step. The Worker does not durably save refresh-token rotations and requires a reviewed persistent-token strategy before public release.

### Worker variables (not added to this repository)

`SPOTIFY_PUBLIC_NOW_PLAYING`: must be the exact string `true` to enable reading the account on the public endpoint. **Default OFF.**

`SPOTIFY_SHARE_TRACK_DETAILS`: must be the exact string `true` to reveal track metadata and artwork when a song is playing. Defaults OFF even when status visibility is ON.

`SPOTIFY_CLIENT_ID` and `SPOTIFY_REFRESH_TOKEN`: Spotify application identifier and private owner credential obtained through the local-only PKCE connection tool. `SPOTIFY_CLIENT_SECRET` is optional only for an existing confidential Authorization Code flow; the new PKCE path does not need it. Never commit any secrets, use them in public URLs, or log token values.

Recommended least-privilege Spotify scope for the first slice: `user-read-currently-playing`. A single personal account is intended. Additional scopes for playlists, top artists, listening history or saved tracks require a separately approved feature and visibility policy. Spotify Developer Mode may require Premium and has restrictions.

The public endpoint intentionally does **not** expose raw Spotify responses, refresh/access tokens, playback context, account identity, device identity, location, or the saved-song library.

The endpoint returns one of:

- `hidden`: sharing disabled by owner. No timestamp or track.
- `playing`: authorized Spotify currently-playing track, status only or curated track title/artist/album/Spotify link and optional official artwork depending on opt-in.
- `off_air`: no active track (paused, 204, unavailable media or private session when indicated). This does not claim Devon is not coding.
- `unavailable`: no valid configuration or Spotify read failure. Never recycle an old track as live.

## Privacy and limits

**Opt in, never opt out.** Production must remain `SPOTIFY_PUBLIC_NOW_PLAYING != true` until the owner sees the public display and consciously enables it. Disabling in the Worker environment will fail closed on subsequent requests but environment propagation across Cloudflare isolates is not instantaneous; do not advertise instant revocation without a separately verified control plane.

The API doesn't guarantee detection of Spotify Private Sessions: the currently-playing endpoint may not include a device private-session flag. Spotify account privacy and this site's explicit public sharing toggle are separate controls. If broadcasting in public is unacceptable during certain listening sessions, keep this site's sharing toggle off.

If the owner enables album covers, public viewers' browsers may fetch images from Spotify's `i.scdn.co` host. The site limits the image host through the Content Security Policy and sets `referrerpolicy="no-referrer"` when loading artwork; third-party image requests can still disclose a visitor's IP address to that host. No other Spotify script is loaded. No autoplay or Web Playback SDK.

The initial Playlists card is a truthful empty state, **not** an implemented synchronization. The same applies to likes and top artists. For the next slice, only explicitly approved public playlists should appear; private saved songs remain hidden.
